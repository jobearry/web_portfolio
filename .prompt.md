Title: Migrate index.html → Plain TypeScript Components (Bootstrap → Tailwind)

Purpose
Create a reproducible prompt that instructs an assistant to migrate the project's `index.html` into a set of standalone plain-TypeScript components and convert Bootstrap classes to Tailwind utility classes. The resulting components must be framework-agnostic (plain DOM APIs + TypeScript), typed, and mountable from a small `src/main.ts` entry.

Assumptions
- Tailwind is already configured and built into `dist/styles.css`.
- Plain TypeScript is preferred (no JS framework). Use `src/components/` for components and `src/main.ts` as the entry.
- Build uses `tsc -p tsconfig.json` to emit `dist/*.js` modules.

Inputs (what the assistant should read)
- `index.html` (project root): full page markup using Bootstrap classes.
- `src/` existing files (for references) and `package.json`.

Desired Outputs
- For each major section in `index.html`, create a TypeScript module in `src/components/` that exports a factory function. Example: `export function createNavbar(): HTMLElement`.
- A `src/main.ts` entry that imports component factories and appends them to a mount node (`#app`).
- Replace Bootstrap classes/structure with Tailwind utility equivalents while preserving semantics and accessibility.
- Minimal DOM behavior implemented in TS (e.g., nav toggle) using event listeners.
- Update `index.html` to include only the mount point (`<div id="app"></div>`) and a single module script tag to the compiled `dist/main.js`.
- Provide a short migration summary and list of changed files.

High-level Steps (to follow when executing the prompt)
1. Parse `index.html` and identify top-level sections to convert into components. Suggested decomposition:
   - Navbar
   - Hero / Introduction
   - AboutMe
   - Projects (and a small `ProjectCard` subcomponent)
   - Contacts / Footer
2. For each section:
   - Extract the HTML markup and convert to a TypeScript factory that creates DOM nodes using `document.createElement` and sets `className` using Tailwind classes.
   - Create a typed `Props` interface only when the section contains dynamic content (e.g., project list, nav links).
   - Replace Bootstrap layout classes (`container`, `row`, `col-...`, grid utilities, `img-fluid`, `text-center`, spacing classes, `d-flex`, etc.) with Tailwind equivalents. Use responsive Tailwind utilities to preserve breakpoints (`sm:`, `md:`, `lg:`).
   - Convert Bootstrap buttons (`btn`, `btn-dark`, `btn-outline-dark`, etc.) into Tailwind-styled buttons (e.g., `inline-flex items-center px-4 py-2 bg-gray-900 text-white rounded`).
3. Implement any interactive behavior in TS (e.g., mobile nav toggle). Keep logic small and unobtrusive and attach it inside the component factory or a small `init` helper exported from component module.
4. Create `src/main.ts` that mounts components into `#app` and demonstrates one example of each component (or renders the full page composition).
5. Update `index.html` to remove the bulk HTML and include the `#app` mount and `<script type="module" src="./dist/main.js"></script>`.

Bootstrap → Tailwind Mapping (common conversions)
- `container` → `container mx-auto px-4` (or `max-w-... mx-auto` depending on desired width)
- `row` → use `flex flex-wrap -mx-4` (and wrap child `px-4`), or `grid grid-cols-1 md:grid-cols-2` when columns are explicit
- `col-<n>` / `col-md-<n>` → `w-full md:w-1/2` (or `md:w-1/3`, etc.), or grid classes `md:col-span-...`
- `img-fluid` → `w-full h-auto object-cover`
- `text-center` → `text-center`
- `d-flex` → `flex`
- `justify-content-center` → `justify-center`
- `align-items-center` → `items-center`
- `btn` / `btn-dark` / `btn-outline-dark` → `inline-flex items-center px-4 py-2 rounded bg-gray-900 text-white` or outline variants using `border` and `text-gray-800`
- `lead`, `display-5`, `display-6` → convert to Tailwind font/size utilities: `text-2xl md:text-4xl font-bold`, `text-xl`, etc.

Constraints & Style
- Use plain DOM APIs in TypeScript (no innerHTML for whole sections unless sanitizing safe static markup).
- Keep components small and focused; export a factory function and minimal types.
- Preserve `alt`, `aria-*`, and semantic elements.
- Prefer Tailwind utility classes only; add small CSS only if Tailwind can't express a style (rare).
- Do not change image paths or external links unless necessary.

Example Component Skeleton (for assistant to follow)
```ts
// src/components/Hero.ts
export type HeroProps = { title: string; subtitle?: string; avatar?: string };
export function createHero(props: HeroProps) {
  const root = document.createElement('section');
  root.className = 'min-h-screen flex items-center';
  const inner = document.createElement('div');
  inner.className = 'max-w-5xl mx-auto px-4';
  // build DOM nodes...
  root.appendChild(inner);
  return root;
}
```

Invocation Template (how a developer should call this prompt)
"Migrate `index.html` into plain TypeScript components. Create components: Navbar, Hero, AboutMe, Projects (+ProjectCard), Footer. Convert Bootstrap classes to Tailwind. Put components in `src/components/`, update `src/main.ts` to mount them into `#app`, and update `index.html` to include only `#app` and the module script. Provide a short migration summary and list of changed files."

Follow-up clarifying questions the assistant should ask if any ambiguity:
- Which sections should be individual components vs. combined?
- Should I keep the original Bootstrap markup in a backup file? (recommended)
- Do you want the Projects list to be data-driven (array of objects) or static markup?

Examples of expected reply after running the prompt
- Files added: `src/components/Navbar.ts`, `src/components/Hero.ts`, `src/components/AboutMe.ts`, `src/components/Projects.ts`, `src/components/ProjectCard.ts`, `src/main.ts`
- Files modified: `index.html`
- Short notes describing mapping decisions and any missing assets or follow-ups.

Limitations
- This prompt does not run builds or update `package.json` dependencies automatically. It will output files for review; the user must run `npm run build:ts` and Tailwind build commands locally to verify final appearance.

Usage Notes
- Save this file as `.prompt.md` in the project root. Use it to generate automated migrations or to instruct an assistant step-by-step.
